# DBAgent 项目架构

> 基于当前代码（2026-10-20）实际摸底整理。入口为 `package/main.py`（4947 行），
> 技能库 28 个，基因组数据 40 原子 / 15 多肽 / 12 蛋白 / 256 超蛋白。

## 1. 一句话概览

DBAgent 是一个「自然语言 → 本地规划 → 沙箱执行」的 agent 系统：

- **规划**：蛋白库 / 超蛋白组合 / 原子 / 规则库 / LLM，五级优先，前四级 0 token；
- **执行**：STOPJ 表达式驱动步骤，技能进沙箱（Linux chroot / Windows 目录隔离），工具在宿主执行；
- **数据驱动**：数据流（吃文件/吃文字）、缺省参数、fan-out 展开、串并行组合全部写在 JSON 里，内核不认识具体技能。

## 3. 启动与入口

- `run.sh`（Linux）/ `dbagent.bat`（Windows）→ `package/main.py`，强制 `PYTHONUTF8=1`。
- `main.py` 子命令：`--setup`、`plan "需求"`、`apply "需求"`、`chat`、`<项目路径>`（结构分析）。
- 有 Key 直接进对话模式，无 Key 弹配置窗。
- 对话模式命令：`/help`、`/stop`、`/queue`、`/clear`、`/mode`、`/analyze`、`/mind`、`/cache`、`/quit`。

## 4. 一次需求的完整链路

```
用户输入
  │
  ├─ /命令拦截（/stop /queue /mode ...）
  ├─ 本地快捷动作 try_local_action（明确操作直接执行）
  ├─ 本地规划 plan_locally(fuzzy)
  │    ├─ 0 级 超蛋白 plan_superprotein（同构并行 / 异构串行组合）
  │    ├─ 1 级 蛋白库 plan_from_protein（规则 → 关键词）
  │    ├─ 2 级 文档多步链 detect_doc_chain（总结→md→ppt）
  │    ├─ 3 级 原子 plan_from_atom（单技能需求）
  │    └─ 4 级 skill-planner 规则库
  ├─ 意图分类 classify_intent → task / code / answer
  │    ├─ task  → run_task → _plan_workflow(LLM) → _run_planned
  │    └─ code  → run_code_agent → agent_loop（后台 worker 线程）
  └─ 都不命中 → call_llm 直接回答
```

**执行编排** `_run_planned(expr, args, ...)`（main.py:3787）：

1. `skill_exec.execute_stopj()` 按 STOPJ 表达式逐步执行；
2. 每步回调 `runner(name, context)`：
   - 工具（`TOOL_HINTS`）→ `execute_tool` → toolset；
   - 技能 → `execute_skill` → 平台沙箱（含流式回调、Key、分支隔离）；
3. 数据流注入按蛋白库声明：`consumes: prev_file / prev_text`、`defaults`、`prefix`、`foreach`；
4. 失败重试 1 次（`WORKFLOW_STEP_RETRIES`）；触发安全策略时让模型改写提示词后重试；
5. `GateRuntime` 做一次闸门复核（展示层）。

**路由优先级**：`/mode` 显式指定 > 本地动作 > 蛋白/超蛋白 > 原子 > 意图分类 > 直接回答。
「继续 / 结果呢」等追问有专门分支（`pending_task`、`last_answer`）。

## 5. 规划体系（数据驱动）

| 层级 | 实现 | 命中方式 | 产出 |
|---|---|---|---|
| 超蛋白 | `plan_superprotein` + `runtime/superprotein.py` | composites.json 关键词 / ≥2 人名同构合成 | 多分支（串/并行） |
| 蛋白 | `plan_from_protein` | `rules` 正则 → `keywords`（长词优先） | 单条技能链 |
| 文档链 | `detect_doc_chain` | 文档格式识别 | 总结→md→docx/pptx |
| 原子 | `plan_from_atom` | 原子名/描述匹配 | 单技能 |
| LLM | `_plan_workflow` | 只在前几级都不命中时调用 | 结构化 steps |

- 蛋白数据：`workspace/data/proteins/index.json`（12 条），节点字段
  `skill / consumes / defaults / prefix / produces_text / foreach`。
- 超蛋白组合：`workspace/data/superproteins/composites.json`（当前 2 条：复刻+新闻、复刻+上下文生图），
  `proteins: ["APV","AWA"]` 引用蛋白代号自动展开技能链。
- 行为参数（尺寸词、人名长度、输出后缀、噪声前缀、生图供应商）集中在
  `workspace/data/runtime.json`，内核只读不写。

## 6. 数据层（生物四层模型）

```
原子 Atom(40)          1 技能 = 1 原子，含 gene_code / strip_words / produces_text 等
   ↓
多肽 Polypeptide(15)   原子组合（skill_chain + atoms）
   ↓
蛋白 Protein(12)       可执行工作流（polypeptide_tree + 数据流声明 + keywords/rules）
   ↓
超蛋白 Superprotein    蛋白组合：256 条四级密码子 + 2 条手工 composition
```

- 存储：`workspace/data/{atoms,polypeptides,proteins,superproteins}/index.json`；
- 超蛋白运行时模式：`SERIAL / PARALLEL / LOOP / ASYNC / PIPELINE`（当前实现 SERIAL、PARALLEL）；
- 技能产出统一落 `workspace/data/work/`，含 `图片/`、`识别结果/`、`上下文/last_prompt.json`。

## 7. 执行层关键机制

### 7.1 沙箱（plat/）

| | Linux（chroot） | Windows（目录隔离） | Termux（目录隔离） |
|---|---|---|---|
| 根 | `/tmp/dbagent-sandbox` | 系统 temp 下同名目录 | `$TMPDIR/dbagent-sandbox` |
| 隔离 | 内核级，仅见 python + busybox + 技能 | 目录边界 + env 白名单 | 目录边界 + env 白名单（无 root 无 chroot） |
| 分支隔离 | `work-<key>` / `skills-<key>` 子目录 | `root-<key>` 独立根 | `work-<key>` / `skills-<key>` 子目录 |
| 解释器 | chroot 内 python3 | 宿主 python | 宿主 python（Termux） |
| 共享依赖 | 整包拷入沙箱 + `/etc/ssl` | 直接读宿主 | 直接读宿主，`DBAGENT_ROOT` 指项目根 |
| 输入搬运 | `translate_inputs` 复制并改写路径 | 宿主路径可直接用 | 宿主路径可直接用 |
| 产出回收 | `collect_outputs` + 重名改名 | 同 | 同 |

### 7.2 流式输出

`run_in_sandbox` 用 `Popen` + 双读线程逐行回调 `on_line(stream, line)`，
子进程注入 `PYTHONUNBUFFERED=1`；`main` 只实时转发 stderr 的阶段行（`[GC]/[GG]`），
stdout 结束后统一展示。

### 7.3 fan-out 与流水线

- 蛋白节点声明 `"foreach": "prev_files" | "prev_texts"`：
  上一步产出 N 个文件/文字就逐个执行，每个条目独立沙箱 key、线程池并发；
- 条目数默认受需求里的张数限制（`_parse_count_words`），未写张数只处理 1 个；
- 相邻 `prev_files → prev_texts` 两步自动**按条目流水线**（识图完立即生图），
  日志显示「流水线：N 个输入并联」；每步计时只记自身耗时（`elapsed_override`）。

### 7.4 上下文与状态

- `_LAST_TEXT_RESULT`：本轮上一步文字（线程局部包装，并行分支互不串味）；
- `_PREV_ROUND_TEXT`：上一轮文字，供「用上一次的提示词」显式复用；
- `context` 工具：读 `work/上下文/last_prompt.json`，跨进程可用；
- `runtime/skillexe_runtime.py`：规划注入 / 步骤记录 / 收尾统计；
- `route_cache.json`：路由与能力问答缓存（技能变更指纹失效）。

### 7.5 Key 池（keypool.py）

- 来源：`DBAGENT_KEYS`、`<project>/key.txt`、`~/.dbagent/key.json`、`agent_coder.json`；
- `acquire/release`：每 key 并发=1，空闲抢占，忙则等待；失败按 401/403（600s）、429/5xx（60s）冷却；
- 接线：每次技能调用与 `call_llm` 都 acquire/release，并行任务自然分摊到不同 key；
- 注意：key 只提升吞吐与容错，不降低单次调用延迟。

## 8. 工具集

`package/tools/sandbox/toolset.py`（CLI 版，进程内调用）：

| 命令 | 用途 |
|---|---|
| read / write / edit | 文件读写（限定 work 目录，编辑支持 replace/insert/delete） |
| ls / grep / find | 目录与内容检索 |
| context | 读取上一次产出的提示词（注入后续步骤） |
| bash | 沙箱内执行 shell（guard 拦截危险命令） |
| fetch / search | 抓网页正文 / 联网搜索（urllib，Bing/搜狗，可选 web_fetch 增强） |

代码任务模式（`agent_loop.py`）走同一套 toolset，另有 `read/write/edit` 的进程内直连实现。

## 9. 代码任务（agent_loop.py）

- 三种模式：`code`（可直接改文件）、`plan`（只给方案）、`goal`（目标驱动循环）；
- 协议：命名参数 `{"tool": "...", "params": {...}}`，`_normalize_call` 兼容旧位置参数；
- 循环上限与停滞检测：`max_rounds×4` 硬上限、连续无改动强停；
- 后台执行：`task_queue.TaskRunner` 单 worker 线程，主线程保持可输入，支持排队/打断/清空。

## 11. 现状与边界

**已具备**：本地 0-token 规划、蛋白/超蛋白/原子复用、串行与并行编排、fan-out 与流水线、
流式输出、失败重试与安全策略改写、上下文跨轮复用、Key 池容错、Linux chroot 隔离。

**已知边界**：

- 单次模型调用 20–35s（识图/生图），总耗时主要由延迟决定，双 key 不改变单次延迟；
- 若两个 key 同属一个账号，服务端仍按账号限流，需实测确认；
- Windows 沙箱是约定式隔离，不能防御恶意脚本访问宿主磁盘；
- 搜图尚未流式化（下载完成才进入识图），首图时间有优化空间；
- visioncustom 输出较长（max_tokens=2000），缩短提示词可降延迟；
- Key 冷却状态仅进程内，多实例共享需落盘 + 文件锁。

## 12. 快速自检

```bash
python3 -m py_compile package/main.py package/skill_exec.py \
  package/keypool.py package/runtime/superprotein.py \
  package/plat/linux/sandbox.py package/plat/win/sandbox.py
python3 -c "import sys; sys.path.insert(0,'package'); import main; print(main.plan_locally('今日新闻'))"
```

验证技能链可直接调 `skill_exec.execute_skill`（绕过对话循环），
无头环境下比反复重启 dbagent 快得多。
